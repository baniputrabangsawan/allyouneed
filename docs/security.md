# Security model and operations

This document records the security boundary for Kits. It is not a claim that the service is
immune to attack. Controls at the Cloudflare edge and on the API host must be configured and
verified independently of repository code.

## Threat model

| Boundary | Public or attacker-controlled input | Privileged operation / protected asset |
| --- | --- | --- |
| Browser → Cloudflare Worker | URLs, query strings, tool input, browser storage | Rendered application and public assets |
| Browser → FastAPI | JSON, entitlement tokens, upload bytes, filenames, MIME headers | Licenses, jobs, results, administrative APIs |
| API → database | Validated schemas and repository parameters | License digests, activations, admin sessions, audit events |
| API → Redis/Dramatiq | Job IDs, queues, rate and concurrency counters | Internal broker and worker capacity |
| Worker → media/AI tools | Hostile images, PDFs, media, subtitles, HTML, options | FFmpeg, PDF/image parsers, Chromium and model memory/CPU |
| API/worker → storage | Generated opaque keys and processed bytes | Temporary uploads and signed results |
| Admin boundary | Password, TOTP, session and CSRF tokens | License lifecycle, audit data and system status |
| Licensing boundary | License key, installation ID, signed entitlement | Paid capabilities and expensive processing |

Highest-risk paths are admin authentication, license activation, public uploads, job creation,
signed downloads, HTML/media parsing, and any queue capable of consuming significant CPU or
memory. Secrets include entitlement private keys, TOTP encryption keys, download signing keys,
database/Redis credentials, Cloudflare/R2 credentials, and admin session cookies.

## Repository-enforced controls

- FastAPI uses explicit credentialed CORS origins and methods.
- Every API response receives anti-sniffing, anti-framing, referrer, permissions and
  cross-origin isolation headers. Production API responses receive HSTS.
- TanStack Start applies a centralized CSP and security headers. Inline script/style is allowed
  only because the current framework hydration and application styling require it; `unsafe-eval`
  is not allowed. Tighten this with nonces when the framework deployment supports them end to end.
- Production startup rejects localhost/wildcard CORS, HTTP public origins, loopback Redis,
  inline jobs, disabled rate limiting, weak download secrets, and unreasonable expiry settings.
- Endpoint-class rate limits distinguish license activation, uploads, job creation, job polling,
  and general API traffic. Expensive mutations fail closed in production if Redis is unavailable.
- Request bodies are streamed and rejected before parsing when they exceed the route limit, even
  if `Content-Length` is omitted or false. Upload streams are separately bounded against their
  server-issued exact size.
- Upload storage keys are generated by the server and resolved inside the storage root. Completed
  uploads cannot be overwritten. Magic bytes, image integrity/dimensions, PDF parsing,
  and PDF page counts are validated before processing.
- Media subprocesses use argument arrays, an executable allowlist, no shell, bounded timeouts,
  cancellation, duration limits, and generic client errors. Job outputs have an explicit size
  ceiling and work directories are cleaned in `finally` blocks.
- Admin authentication uses Argon2id, generic credential errors, server-side hashed sessions,
  secure production cookies, SameSite Strict, CSRF validation, TOTP/recovery codes, rate limiting,
  session revocation and audit events.
- License keys are stored as digests. Ed25519 entitlement tokens are checked against current
  license/activation status and required capabilities on protected processing endpoints.
- Result downloads use short-lived HMAC-signed URLs and constant-time signature comparison.

## Severity-ranked findings

### High

- The API origin must be made unreachable except through Cloudflare. Repository code cannot
  establish host firewall or Tunnel policy. Until that is done, edge WAF and bot rules can be
  bypassed by reaching the origin directly.
- Anonymous job and upload status resources currently rely on opaque identifiers. Before exposing
  a durable multi-user API, bind each resource to an installation/session or a separate scoped
  access token and enforce that ownership on every read, cancel, completion and result operation.

### Medium

- The CSP still permits inline scripts and styles for framework compatibility. Introduce a
  per-response nonce after verifying TanStack hydration, theme bootstrap and style behavior.
- Local upload issuance state is process-local. Production should use R2 presigned operations or
  shared Redis-backed issuance records with expiry and one-time completion semantics.
- Parser isolation is process-level only. Run media/PDF/Chromium workers in restricted containers
  with memory/CPU/PID limits, a read-only base filesystem and isolated temporary volumes.

### Low

- Dependency and static-analysis findings need regular triage; a clean scanner run is not proof of
  safety. Do not perform unreviewed major upgrades solely to silence audit output.

## Required infrastructure configuration

1. Put both web and API DNS behind Cloudflare. Force HTTPS, use TLS 1.2+, enable managed WAF rules,
   DDoS protection, bot analytics and narrowly scoped rate rules for `/api/`, `/admin/`, license
   activation, uploads and jobs. Do not challenge verified Googlebot/Bingbot or public SEO files.
2. Prefer Cloudflare Tunnel for the API. Otherwise firewall 80/443 to the intended reverse proxy
   path. Keep Redis, the database and Dramatiq private. Use SSH keys, disable root/password login,
   and enable security updates.
3. Set `TRUST_CLOUDFLARE_IP_HEADER=true` only after direct-origin access is blocked. Otherwise a
   client could spoof that header to evade application limits.
4. Store all secrets in the deployment secret manager. Rotate entitlement signing keys with key
   IDs and an overlap window; rotate session/download secrets by expiring active tokens; rotate
   TOTP encryption keys with an explicit decrypt/re-encrypt migration; rotate R2/database/Redis
   credentials at the provider, update secrets, deploy, then revoke old credentials.
5. Protect and encrypt database backups, automate retention, and perform periodic restore tests.
   Disaster recovery must cover database corruption, host compromise, signing-key compromise,
   failed deployment and storage loss.
6. Enable DNSSEC only after confirming Cloudflare is authoritative. Add SPF/DKIM/DMARC only when an
   actual mail provider is configured.

## Production verification

Verify HTTPS redirect/HSTS, CSP and security headers with public requests. Confirm the sitemap and
robots files remain public. Exercise anonymous/free/Pro/expired/revoked/wrong-capability cases,
admin CSRF and session expiry, oversized and malformed uploads, rate limiting, queue saturation,
worker timeout/cleanup and signed-download expiry. Alert on abnormal 403/429/500 rates, login
failures, queue depth, job creation, CPU/memory/disk pressure and repeated invalid entitlements.
